# Flat Editorial — demo (visual reference only)

A React + Tailwind CSS app rendering this template's two page patterns
and the components they compose, so a human can see what "Flat
Editorial" looks like before choosing it.

Two routes, reachable from the header:

- **Latest** — `patterns/home-feed.md`: a lead article above a grid of
  Article Cards, with pagination and a subscribe block.
- **Article** — `patterns/article.md`: a full article page, which is
  what the whole template exists to produce. It renders every element
  `specs/prose.md` styles — headings, links, lists, a blockquote, a
  pull quote, a figure, a callout, a table, inline code and a code
  block — plus the table of contents, the byline, the tags, the author
  block and the subscribe form.

**This app is not the source of truth for the template**, and an AI
agent generating code for a real project must never copy markup, class
names, or components from `src/` here. The source of truth is:

- `../tokens/*.json` — design tokens
- `../foundations/*.md` — cross-cutting rules
- `../specs/*.md` — component specs
- `../patterns/*.md` — page composition patterns

See `/AGENTS.md` at the repository root for the full rule set.

## How the tokens reach this app

`scripts/build-tokens.mjs` reads every file in `../tokens/*.json` and
writes `src/tokens.generated.css` as CSS custom properties.
`tailwind.config.js` maps Tailwind's theme to those variables, so every
utility class in `src/` resolves back to a token — nothing here is a
hand-picked hex or pixel value.

The dark theme is a mirror at `color.dark.*` / `shadow.dark.*`. The
script strips the `dark` segment and routes those values into their own
block, so **both themes drive the same custom property**: `:root` holds
light, `[data-theme="dark"]` holds dark, and a `prefers-color-scheme`
query applies dark to `:root:not([data-theme="light"])` — which is what
makes an explicit choice win in both directions.

`src/tokens.generated.css` is not committed (see `.gitignore`); it is
regenerated by `npm run dev` / `npm run build`.

## The libraries it depends on

Each exists because a foundation or a spec requires what it provides,
and each is a **demo-local choice**, not part of the template.
`foundations/libraries.md` lists alternatives per ecosystem.

| Dependency | Why | Required by |
|---|---|---|
| `@fontsource-variable/source-serif-4` | the reading serif the tokens name, self-hosted and versioned | `foundations/typography.md` |
| `@fontsource-variable/inter` | the chrome sans | `foundations/typography.md` |
| `@fontsource-variable/jetbrains-mono` | the code face | `foundations/typography.md` |
| `lucide-react` | one coherent, stroke-based icon family, inline SVG inheriting `currentColor` | `foundations/iconography.md` |

That is the whole list, and the shortness is the point: this template
specifies very few icons and no charts, maps or avatars-by-library.

**No syntax highlighter is installed.** `specs/code-block.md` defers
that to `foundations/libraries.md`, which requires a build-time
highlighter themed from this template's own tokens and warns that
highlighter themes routinely ship colours below 4.5:1. Adding an
unthemed one to make the demo prettier would misrepresent the
contract, so code renders plain and the requirement stays visible.

## What to look at

Things easier to check by hand than to read:

- **The measure.** The article's text column stops at roughly 68
  characters no matter how wide the window gets — that is
  `font.measure.prose`, and it is the token with no counterpart in the
  `adminlte-classic` template.
- **What breaks out of it.** The cover, the figure, the table, the
  pull quote and the code block all widen past the text column; the
  figure's caption pulls back to it. That alternation is one of the
  few structural rhythms a page with no shadows has.
- **Heading spacing is asymmetric.** The gap above a section heading
  is four times the gap below it, so the heading visibly belongs to
  the text that follows.
- **Links in prose are underlined at all times**, not on hover.
- **No shadows anywhere** — except one. Narrow the window below 768px
  and open the navigation: that panel is the template's only
  `shadow.overlay`, and it is allowed because the panel floats over
  content and shares its background.
- **Both themes.** The toggle honours the system preference on first
  load, and an explicit choice beats it in both directions. Note that
  a tag flips from white-on-violet to near-black-on-pale-violet: the
  accent inverts in lightness, so `text.on-accent` inverts with it.
- **The text-only card.** In the feed, the article with no cover sits
  in the same grid as the rest and its date still lines up with its
  neighbours' — no placeholder rectangle.
- **Keyboard.** Tab from the top hits "Skip to content" first.
  Activating a table-of-contents entry moves focus to the heading, not
  just the scroll position. Tab to a code block and it scrolls with
  the arrow keys.
- **The permalink beside each section heading** appears on hover for
  pointer users and is always reachable by keyboard.

## What this demo fakes, and how

Worth stating so nothing here is mistaken for a template rule:

- **The cover images are flat colour bands, not photographs.** The
  demo ships no real imagery. `foundations/imagery.md` requires real
  assets in a real project, and its rules — square corners, no frame,
  no shadow, a required caption width — are what the bands are drawn
  to demonstrate. They are `aria-hidden`, standing in for a
  photograph; per that foundation a photograph is *not* dimmed or
  filtered between themes, which is why they stay bright in the dark
  theme.
- **The articles are written for the demo.** Only the first has a
  body; the rest exist so the feed and the pagination have something
  real to lay out. They are about typography because a blog demo
  filled with lorem ipsum shows the layout and none of the thing this
  identity is built around.
- **The subscribe form has no backend.** Its delay exists only so the
  loading state `specs/button.md` defines is visible.
